# Тестовое задание: автоматизация тестирования формы авторизации

Данный проект представляет собой выполнение тестового задания.  
Для выполнения задания был выбран сайт литературных публикаций [https://author.today](https://author.today)

В основу архитектуры решения положены подходы:
- POM (Page Object Model)
- **PEM** (Page Elements Model)

## Используемые технологии и зависимости

Проект использует менеджер пакетов **Poetry** и содержит следующие зависимости:
playwright - Взаимодействие с GUI web-приложений 
pytest - Управление тестами
pytest-playwright - Интеграция pytest и playwright
pytest-rerunfailures - Перезапуск flaky тестов
allure-pytest - Сбор статистики и генерация отчётности
pydantic - Валидация моделей данных
pydantic-settings - Управление настройками из .env и переменных окружения

## Тестовые сценарии

В проекте реализованы два тестовых сценария на основе указанных в задании действий. Поскольку доступ к правилам ФЛК (форматно-логического контроля) ввода по естественным причинам отсутствует, для тестов были выбраны следующие комбинации значений:

### Валидные данные
- Валидный логин (email) + валидный пароль

### Невалидные данные
- Пустой логин (email) + валидный пароль
- Валидный логин (email) + пустой пароль
- Пустой логин (email) + пустой пароль
- Валидный логин (email) + невалидный пароль
- Невалидный логин (email) + валидный пароль

### Что проверяют тесты

- Валидный вход в систему
- Обязательность заполнения полей формы авторизации и отработку сообщений о заполнении
- Реакцию системы на ввод неверного пароля или неверного логина

> **Примечание:** При составлении комбинаций учитывалось правило «Одно невалидное значение среди других валидных на один негативный тест». Тест с отсутствием значений ввода в обоих полях используется для проверки, что сообщения появляются для каждого поля отдельно — необходимое исключение из правила. Длины значений не учитывались, так как нет доступа к реальным правилам ФЛК.

## Архитектура решения

Для написания решения и демонстрации навыков использовался минимум элементов:
- Для страниц, не связанных с формой авторизации, выбрано несколько элементов, по наличию и содержанию которых можно оценить, что «пользователь» находится на нужной странице
- Для формы авторизации использованы: поля формы, кнопка входа, сообщения о неверном вводе/отсутствии значений, кнопка входа на страницу авторизации и кнопка выхода из аккаунта

## Особенности реализации

- **Кроссбраузерность:** реализовано выполнение тестов в трёх браузерах (Chromium, Firefox, WebKit)
- **Отчётность:** сбор статистики и генерация отчётов в Allure
- **Артефакты:** к тестам прикрепляются видеозаписи и trace-отчёты (последовательность снэпшотов в соответствии с выполнением кода)

> **Примечание:** Параллельный запуск тестов не используется ввиду малого количества тестов.

## Установка и запуск проекта

### Требования

- Python 3.13.12 или выше
- Poetry 2.1.4 или выше

### 1. Клонирование репозитория

```bash
git clone https://github.com/Uriy-T/test_task.git
```

### 2. Установка Poetry (если не установлен)

```bash
pip install poetry
```

### 3. Установка зависимостей

Проследите, чтобы у вас использовался интерпретатор не ниже указанной версии и чтобы он использовал poetry.
В этом случае, при открытии проекта в PyCharm Poetry самостоятельно установит все необходимые зависимости из toml файла.
Если этого не произошло, попробуйте выполнить команду:
```bash
poetry install
```

### 4. Установка браузеров Playwright (если не установлены)

```bash
poetry run playwright install
```

### 5. Конфигурация и данные окружения

В силу того, что это тестовое задание, для удобства проверки прилагаются файлы `config.py` и `.env`.

### 6. Запуск тестов

Файл `pytest.ini` содержит параметр `addopts` со значением `-s -v --alluredir=./allure-results`, что автоматически запускает тесты с генерацией отчётов, прикреплением видео и trace-отчётов.

#### Команды для запуска

python -m pytest - Полный прогон всех тестов в проекте
python -m pytest -k '<название тестов или маркировок>'` - Запуск тестов по категориям или конкретным сценариям

> **ВНИМАНИЕ!**  
> При запуске очередного прогона, чтобы не смешивались данные о прохождении тестов от прошлых прогонов, убедитесь, что удалены папки `allure-results`, `tracing` и `videos`.

## Просмотр Allure-отчёта

### Быстрый просмотр (с локальным сервером)

```bash
allure serve ./allure-results
```

### Генерация статического отчёта

```bash
allure generate ./allure-results -o ./allure-report
```

Запустить такой отчёт можно:
- В ручную из HTML-файла в корне папки `allure-report`
- Или командой:

```bash
allure open ./allure-report
```

### Обновление существующего отчёта

Если у вас уже имеется сгенерированный Allure-отчёт, после нового прогона можно сгенерировать новый отчёт с очисткой старого:

```bash
allure generate ./allure-results --clean -o ./allure-report
```
